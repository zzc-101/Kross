# 2026-08-24 后端审查

范围：`backend/` 全量（176 个 Java 文件），覆盖安全与身份（security / identity /
channel token）、编排与多机（orchestrator / fleet / catalog / storage）、核心
Agent 链路（agent / channel / controller）三条线。结论来自代码审查，按严重度
排列。状态已于 2026-08-25 按当前分支重新核对；误判和仅涉及兼容性的项目不再
作为缺陷待办。

## 总体评价

做得好的：session fixation 防护；token 只存哈希 + 邀请码 CAS 原子核销；
bootstrap 行锁 + partial unique index 双防竞争；AES-GCM 用法正确（随机 IV、
128-bit tag）；MyBatis 全参数化，无 SQL 注入面；Docker 名称经 SHA-256 派生、
不经 shell；Skill 包路径穿越校验正确；job 认领 `FOR UPDATE SKIP LOCKED`
无竞态；属主校验全面，未发现绕过 `OrganizationAccess.require` 的越权路径。

## 与 2026-08-21 审查的衔接

- 上轮已修项（SSO 仅按已验证邮箱绑定、bootstrap 唯一超管、reconcile 与 wake
  解耦、starting 宽限等）复核有效；`email_verified == null` 缺口也已补齐。
- 上轮「公网 Nginx 不反代 /internal/」缓解了本轮回第 9 条低危配置惯性的直接
  利用面，但 Spring 侧 permitAll 未收紧。

## 建议优先顺序

1. 当前没有未修的 High 项。
2. 生产启用 SSO 时配置 HTTPS `KROSS_EXTERNAL_BASE_URL` 与 HTTPS issuer。
3. 只有在引入不可信同站子域或控制面多副本时，再分别实施 CSRF token/Origin
   校验与事件总线、调度选主改造；不提前建设兼容层。
