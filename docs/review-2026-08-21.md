## 本次先修

1. 公网 Nginx 不再反代 `/internal/`。Worker 与 `kross-node` 直连控制面（Compose
   别名 `kross-server:8787`，集群再单独映射内部端口 `8788`）。
2. `reconcileRuntimeAgents` 把消息重排与 `wake()` 拆开：`wake()` 失败不得回滚
   已入队的用户消息。

## 安全

| 严重度 | 位置 | 问题 | 状态 |
|---|---|---|---|
| Critical | `NodeHandshakeInterceptor` / `NodeWebSocketHandler` | 全集群共用 `KROSS_NODE_TOKEN`，`nodeId` 由调用方指定，`node.hello` 可改写 handshake 中的节点 ID。冒充节点后可拿到明文 `agentToken`，再经 `agent.model_environment` 取得组织模型密钥。 | **已修**：令牌按 `nodeId` 绑定；hello/heartbeat 不得改写握手 ID |
| High | `docker/web.nginx.conf` | 用户入口 `:8787` 反代 `/internal/`，Spring 对该路径 `permitAll`。 | **已修**：公网 vhost 对 `/internal/` 返回 404；节点/Worker 走控制面内部地址 |
| Medium | `worker/src/transport.ts` | Agent Token 放在 WebSocket query，可能进入 Nginx access log。 | **已修**：握手改 `kross.bearer.` 子协议 / `Authorization: Bearer`，不再接受 query token |
| Medium | `SsoService.provision` / `canLink` | 本地密码用户没有 email 时，SSO 按 `preferred_username` 自动绑定，IdP 同名账号可能接管。 | **已修**：只按已验证 email 绑定已有账号 |
| Medium | `AuthService.register` | 空库首次注册无互斥，并发注册可能产生多个 `super_admin`。 | **已修**：advisory lock + `users_one_super_admin` 唯一索引 |

登录/登出落库与 JSON/MDC 日志未发现密码或 Token 写入。OIDC 的 PKCE、`state` /
`nonce`、JWKS，以及 JuiceFS 路径前缀校验，审查认为可以接受。

## 缺陷

| 严重度 | 位置 | 问题 | 状态 |
|---|---|---|---|
| High | `AgentService.reconcileRuntimeAgents` | `@Transactional` 内先 `requeueInterruptedMessages` 再 `wake()`。`wake()` 抛错会整段回滚，用户消息回到 `processing`，对话卡住。 | **已修** |
| High | 同上 | `listRuntimeAgents` 含 `starting`。inspect 还不是 `running` 时会被当成崩溃并强制重建。 | **已修**：`starting` 在 `start-timeout-ms` 宽限内跳过 |
| Medium | `AgentService.claimJob` | 中断后 agent 占位标 `failed`，`findReplyTo` 仍复用且不改回 `processing`，SSE 会先推一条失败助手消息。 | **已修**：复用失败占位时改回 `processing` 并清空 `error_summary` |
